# Комплексная предрелизная проверка Docflow

Цель — принять обоснованное решение о выпуске конкретного кандидата. План охватывает архитектуру, данные, бизнес-процессы, интерфейс, качество тестов, безопасность, производительность и эксплуатацию.

Исходные материалы: [README](../README.md), [техническая документация](tech_docs.md), [инструкции эксплуатации](instructions.md), [тестовая инфраструктура](../testing/README.md), [команды проверок](../build/make/checks.mk), [состав release gate](../tools/release-gate.sh).

## Как выполнять план

- Единица работы — один номер. «После» указывает номера обязательных предшественников. Для строк, которые образуют матрицу, создавайте экземпляры задания по каждому объекту, например `34/Windows/регистратор` или `19/журнал/ограниченная роль`. Строка закрывается, когда учтены все её экземпляры.
- Перед началом прочитайте результаты предшественников и выберите один экземпляр. Запишите номер, SHA, версию артефакта, стенд, исходные данные, ожидаемый и фактический результат, ссылку на доказательство и статус. Если найдена проблема, добавьте идентификатор дефекта, серьёзность и владельца. Удалите секреты и персональные данные из прикладываемых материалов.
- Статусы: «ожидает», «в работе», «пройдено», «не пройдено», «заблокировано», «неприменимо». При блокировке укажите недостающий доступ, стенд, вводные или решение и продолжите независимые шаги. Неприменимость требует обоснования. Падение закрывает выполнение проверки с дефектом и остаётся входом для исправления.
- Проверки с изменением данных, отказами и нагрузкой выполняйте на изолированных стендах. `make integration-test` и `make db-performance-check` используют один Compose-проект и удаляют его тестовые тома, поэтому их запуски нужно развести. Не передавайте рабочие учётные данные и DSN в тестовые команды.
- Доказательства храните в каталоге проверки или системе задач. Штатные локальные отчёты можно брать из `build/release-evidence/`, `build/performance/` и `build/transition-evidence/prod-compose-smoke/`. При смене кандидата отметьте затронутые результаты и повторите их по шагу 72.
- Для передачи работы достаточно указать готовые номера, незавершённые экземпляры, дефекты, ссылки на доказательства и ближайший доступный номер. Процент строк покрытия служит ориентиром, а решение о выпуске опирается на проверку рисков.
