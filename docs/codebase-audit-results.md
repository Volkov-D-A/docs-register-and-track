## Актуальное решение по совместимости

Для третьего прохода пользователь подтвердил: рабочей БД нет, приложение находится
в разработке, поддержка прежних контрактов и сохранённых данных не требуется.
Решения прежних проходов ниже являются историей: S01, S03 и часть S04

зависимостей, поиск повторяющихся блоков и разбор найденных цепочек до SQL,

необходимые защитные и тестовые механизмы сохранены с обоснованием ниже.

Исходно в рабочем дереве уже были удалены `codebase-cleanup-audit-plan.md`,

Эти удаления не восстанавливались и не включаются в объём удалённого аудитом кода.

Статические проверки охватывали `main.go`, `cmd`, `internal`, `frontend/src`,
тесты, `tools`, `scripts`, `testing`, manifests, сборочные конфигурации и
документацию. Это не утверждение о построчном ручном прочтении каждого файла:

обновлены штатной Linux-сборкой; ручных изменений генерации нет.

## Карта системы и охвата

Основная цепочка: React pages/hooks → generated Wails bindings → desktop
services → serverclient → HTTP handlers → серверные services/ports → repository
→ PostgreSQL и transactional outbox → worker → SSE → обновление UI.

Отдельные входы: CLI `run`, `check-config`, `healthcheck`, `build-info`, `version`;
startup/shutdown desktop и сервера; background lifecycle; backup scheduler и
координатор replacement/recovery; генераторы release assets; Makefile и tools.

## Проверенная совместимость и осознанно сохранённое

| ID | Элемент | Решение, причина и условие пересмотра |
| --- | --- | --- |
| S01 | Cursor и page/totalCount | На первом проходе page использовался в `LinksTab`; на втором селектор переведён на cursor. Page-ветка пока сохранена в HTTP-контракте и сценариях `tools/dbperf`. Её снятие требует решения по этим потребителям; пагинация пользовательских событий независима |
| S02 | Audit payload без audience | Сохранён conservative resync. Audience отсутствует у старых durable payload, а nil также означает широкую capability invalidation. Пересмотр после проверки producer и всех сохранённых/восстанавливаемых очередей |
| S03 | Ключ `backup:<job>:<terminal-stage>` | Сохранён: локальные job/operation journals переживают restart и replay после restore; изменение ключа может повторно записать уже доставленный audit. Пересмотр только с переходом существующих dedup keys |
| S04 | Отказ от старых backup-архивов | Сохранён: каталог должен распознавать несовместимость и блокировать опасное восстановление. Негативные тесты не являются поддержкой старого восстановления |
| S05 | Build protocol 2, версия и fingerprint | Сохранены: рабочий bootstrap проверяет точное соответствие клиента и сервера; mismatch/required-ветви ограничивают доступ, а не исполняют старую архитектуру |
| S06 | Schema compatibility/readiness | Сохранены: базовая миграция требует пустую БД, background и API зависят от версии/dirty state. Наличие одной миграции не делает эти проверки ненужными. Существующие БД не модифицировались |
| S07 | `CreatedBy`, `CompletedAt/By`, planned due date, current control ID | Сохранены: доменная история сериализует before/after, метаданные сохраняются при командах; recurrence использует planned date и текущий контроль. Отсутствие прямого React-чтения не доказывает ненужность данных |
| S08 | Дубли корневых/видовых реквизитов документов | Сохранены: общие поиск, доступ и граф читают корневую сущность, видовые запросы — details. Смена хранения требует отдельного решения по схеме и согласованности, а не удаления одной записи |
| S09 | `Enqueue`, `ProcessOnce`, default constructors и integrationdb | Сохранены как используемые тестовые seams: внешние test packages вызывают настоящие repository/worker/client, а не отдельную реализацию бизнес-операции. У них есть актуальные integration/unit consumers |
| S10 | Моки server ports | Найдены consumers в текущих services tests. Моки не удалялись только из-за отсутствия production-вызовов: это их назначение. Старый restore-тест и тесты мёртвых мапперов, напротив, удалены/перенесены |
| S11 | Synthetic schema versions в DTO/API tests | Сохранены: проверяют сериализацию и сравнение состояний, не заявляют реальную версию embedded schema. Массовая замена на 1 скрыла бы смысл части сценариев |
| S12 | Общие страницы и похожие command handlers | Сохранены различия полей, required/optional validation, свежего чтения перед edit, permissions и idempotency. Общая оболочка уже есть в `DocumentKindPage`/hooks; повтор кода сам по себе не основание для универсального handler |
| S13 | HTTP server/client interfaces | Похожая форма описывает разные стороны контракта. Общие transport DTO допустимы; переиспользование server implementation из desktop запрещено границей архитектуры |
| S14 | Recovery polling, SSE resync, cancellation | Сохранены: восстановление наблюдается независимо от login session, resync восстанавливает состояние после пропуска событий, latest/coalesced requests защищают от устаревших ответов |
| S15 | Go/npm dependencies | Для всех 12 direct Go modules найдены imports, включая тесты. Frontend dependencies используются приложением, конфигурацией или тестами. Manifests/lockfiles не менялись; обновление версий не выполнялось |

| S17 | P99 в `tools/dbperf` | Сохранён: это отдельное измерение с выводом в performance snapshots и отчёты; оно не относится к удалённым внутренним registry-полям без потребителя |

## Ограничения первого прохода

Полный `release-gate`, полный backup/SMB Compose smoke, frontend component suite,
desktop Linux/Windows builds и Windows runtime в этой задаче не запускались.
HTTP/Wails DTO и экспортируемые Wails-методы не менялись, поэтому bindings не
перегенерировались. Frontend-код не менялся; TypeScript использован для аудита.
Production данные и статистика использования индексов не исследовались.

Аудит подтверждает найденные и проверенные цепочки в текущих исходниках.
Он не гарантирует отсутствие любого мёртвого кода во всех внешних окружениях.
Для последующих изменений сохраняется правило: обходить затронутую цепочку
целиком и фиксировать конкретное условие снятия оставленной совместимости.
