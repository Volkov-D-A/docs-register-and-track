# Рабочий стол

Рабочий стол показывает текущую работу пользователя на основании фактических прав и участия в документообороте. UX-профили `admin`, `clerk`, `executor` и `mixed` не определяют состав экрана и не используются для авторизации. Сервер ограничивает данные теми же правилами, что и соответствующие операции с поручениями, ознакомлениями и документами.

## Поручения

Блок поручений имеет два режима:

- **Исполнение** — поручения, где пользователь является исполнителем или соисполнителем, а также поручения тех, кого он активно замещает. Здесь видны новые поручения, работа в процессе, возвращённые на доработку и сроки исполнения.
- **Контроль** — поручения по документам, для которых пользователю доступно действие `assign`. Здесь видны поручения в работе, просроченные и исполнения со статусом `completed`, ожидающие приёмки.

Обычно доступен один режим. Если доступны оба, в заголовке блока появляется переключатель «Исполнение / Контроль»; заголовок и показатели меняются вместе с режимом. Каждый режим сохраняет собственный серверный scope. Право `assign` действует по видам и конкретным документам, поэтому режим контроля нельзя определять по факту создания поручения или по UX-профилю. Если нужен контроль только *созданных пользователем* поручений, это отдельное бизнес-правило, которое следует согласовать до реализации.

## Ознакомления

Блок ознакомлений устроен аналогично:

- **Мои ознакомления** — задачи, ожидающие подтверждения от пользователя или тех, кого он активно замещает.
- **Контроль ознакомлений** — активные задачи по документам, для которых доступно действие `acknowledge` и разрешён просмотр конкретного документа.

При доступности обоих режимов показывается переключатель с изменением заголовка. Право `create` или `read` само по себе не даёт режим контроля ознакомлений.

## Сводка и переходы

Верхняя часть рабочего стола показывает показатели выбранных режимов: новые поручения, просроченные и приближающиеся сроки, ожидающие ознакомления и исполнения на приёмке. Показатели рассчитываются по текущему состоянию задач на сервере. «Новое поручение» означает состояние поручения `new`, а непрочитанное событие — отдельный показатель; открытие уведомления не завершает задачу. Каждая карточка открывает соответствующий список с тем же scope и фильтром либо конкретный документ. Списки и счётчики должны совпадать по правилам доступа, статусам, замещению и границам дат.

Быстрые действия регистрации показываются отдельно для каждого вида документа с доступным действием `create`. Пользователь с несколькими полномочиями видит совокупность доступных действий, без назначения ему единственного профиля. Администратор без участия в документообороте и без документных прав не получает фиктивных рабочих задач.

Дополнительный блок «Новое для меня» может показывать последние персональные события: назначение поручения, изменение его статуса и задачу ознакомления. Существующие пользовательские события и SSE служат сигналом обновить экран; источником истины остаются серверные запросы. Событие о добавлении файла потребует отдельной реализации. При переходе из события доступ к документу проверяется заново.

## Переход от текущего дашборда

Рабочий стол получает доступные режимы, счётчики и предпросмотр из нового серверного API. Список поручений принимает тот же режим и показатель; ознакомления открываются в постраничном списке. Прежняя развилка `resolveUserProfile` и сводка `dashboard/activity` удалены. Правила HTTP-контракта и известное ограничение соисполнителей описаны в `docs/tech_docs.md`.
