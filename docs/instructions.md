# Установка обновление языков

1. Golang
 rm -rf /usr/local/go && tar -C /usr/local -xzf go1.26.4.linux-amd64.tar.gz

2. NodeJS
nvm install 24

# Обновление пакетов проекта
1. Бэкенд
Вы можете посмотреть список доступных обновлений с помощью команды:
go list -u -m all
Обновить все пакеты до последних минорных версий/патчей:
go get -u ./...
go mod tidy
go install github.com/wailsapp/wails/v2/cmd/wails@latest

2. Фронтенд
Проверить устаревшие пакеты:
npm outdated
Безопасное обновление (минорные версии и патчи):
npm update
Обновление до последних мажорных версий (с осторожностью):
npx npm-check-updates -u (npx npm-check-updates -i интерактивный режим)
npm install

# Актуализация рабочего места после обновления:
1. Подтягиваем зависимости Go (Бэкенд)
go mod download

2. Устанавливаем зависимости фронтенда (Чистая установка)
cd frontend
npm ci

# Тестовое обновлени через git branch:
1. Подготовка (Чистый лист)
git status

2. Создание «песочницы»
git switch -c test-major-updates

3. Эксперимент (Обновление)
npx npm-check-updates -i
npm install.

4. Принятие решения (Два пути)
Сценарий А: Успех! Всё работает отлично.
git add .
git commit -m "chore: update vite and typescript to latest major versions"
git switch main
git merge test-major-updates
git branch -d test-major-updates

Сценарий Б: Провал. Всё сломалось.
git switch main
git branch -D test-major-updates
cd frontend
npm ci

## Серверное резервирование и восстановление

Сервер резервирует PostgreSQL в архив формата 4 с `manifest.json` и
`database.dump`. SeaweedFS и документные вложения исключены из новой модели.
Архивы прежних форматов несовместимы; существующие копии автоматически не удаляются.

Перед запуском Compose создайте три файла вне Git и укажите абсолютные пути
`POSTGRES_PASSWORD_FILE_PATH`, `SEQ_ADMIN_PASSWORD_FILE_PATH`,
`DOCFLOW_SETTINGS_KEY_PATH` в `.env`. Файлы содержат значение без `NAME=`.
Ключ настроек создаётся командой `openssl rand -base64 32`. Каталог секретов
должен иметь права `0700`; файлы PostgreSQL и ключа — владельца UID 65532 и права
`0400`, чтобы сервер мог их читать. Файл Seq может принадлежать root с правами
`0400`. Сохраняйте ключ при перезапусках: без него сохранённый SMB-пароль не расшифровать.

В «Настройки → Резервирование» администратор задаёт SMB-сервер, общий ресурс,
каталог, учётную запись, пароль, расписание и число сохраняемых копий.
Резервирование по расписанию относится к резервным копиям; пользовательские
отчёты создаются только по запросу. Сохраняйте staging volume: в нём находятся
состояние заданий, неотправленные архивы и маркеры незавершённого восстановления.

Восстановление выполняется через каталог копий в админпанели: сначала проверка,
затем подтверждение замены данных. Требуется выделенная PostgreSQL приложения.
Сервер создаёт локальную страховочную копию, блокирует бизнес-операции, заменяет
БД и при ошибке пытается откатить замену. Не удаляйте staging при незавершённой
замене. После успеха все сессии отзываются, расписание резервирования и SMB-пароль
очищаются: войдите повторно и настройте их заново. Seq, ключ настроек и другие
секреты не входят в архив; шифрование самого архива не реализовано.

Для полного восстановления после потери БД создайте пустую выделенную БД,
запустите согласованную сборку сервера и desktop, создайте первого администратора
и подключите SMB с новой совместимой копией. Восстановление старых данных
прежней модели не предусмотрено. Новый baseline 001 создаёт всю схему на пустой БД.
Обновление и сброс работающего окружения не выполнялись.

`make storage-down` останавливает стек с сохранением данных. `make storage-reset`
удаляет тома текущего Compose-проекта и пересоздаёт стек; используйте эту команду
только для согласованного сброса. Старые SeaweedFS volumes не входят в новый Compose
и автоматически не удаляются. Перед сменой production-сборки выполните пробное
восстановление и сохраните подтверждение. `make integration-test` использует
изолированный PostgreSQL/Samba; нужны Docker Compose и совместимые PostgreSQL
client tools (`pg_dump`, `pg_restore`).
